# 复测验证流程

## 概述

当缺陷修复后，需要进行复测验证，确认缺陷已正确修复。

---

## 流程步骤

### 1. 监控 Issue 状态

| 状态 | 含义 | 测试动作 |
|------|------|---------|
| `Open` | 待处理 | 等待 |
| `In Progress` | 开发处理中 | 等待 |
| `Fixed` | 已提交修复 | **触发复测** |
| `Verified` | 复测通过 | 准备关闭 |
| `Closed` | 已关闭 | 归档 |
| `Reopened` | 复测失败 | 补充信息 |

查看 Issue 状态：

```bash
# 查看指定 Issue 状态
gh issue view {issue-id} --json state,title

# 查看所有待复测 Issue
gh issue list --label fixed --state open
```

---

### 2. 确定复测范围

| 范围类型 | 说明 | 用例数 |
|----------|------|--------|
| **最小范围** | 仅复测失败用例 | 1-3 个 |
| **模块范围** | 复测相关模块全部用例 | 5-10 个 |
| **关联范围** | 复测可能受影响的用例 | 10-20 个 |
| **全量回归** | 版本发布前全部用例 | 全部 |

**范围选择原则**：
- P0 缺陷 → 模块范围或关联范围
- P1 缺陷 → 最小范围或模块范围
- P2 缺陷 → 最小范围

---

### 3. 执行复测

按照原测试用例执行，重点验证：

1. **原失败断言** — 是否已修复
2. **边界场景** — 修复是否引入新问题
3. **关联场景** — 其他用例是否受影响

---

### 4. 复测通过处理

```bash
# 1. 评论 Issue
gh issue comment {issue-id} --body "复测通过，验证记录: [TC-{ID} 复测报告](链接)"

# 2. 添加标签
gh issue edit {issue-id} --add-label verified

# 3. 关闭 Issue
gh issue close {issue-id} --comment "修复验证通过，Issue 关闭"
```

---

### 5. 复测失败处理

```bash
# 1. Reopen Issue
gh issue reopen {issue-id}

# 2. 补充失败信息
gh issue comment {issue-id} --body "$(cat <<EOF
## 复测失败

复测批次: {date}_{seq}-regression-fail
复测报告: [TC-{ID} 复测报告](链接)

失败详情:
- 预期: {预期值}
- 实际: {实际值}

建议重新检查修复方案。
EOF
)"

# 3. 添加标签
gh issue edit {issue-id} --add-label regression-failed
```

---

### 6. 创建复测报告

复测报告目录命名：
```
{date}_{seq}-regression-pass
{date}_{seq}-regression-fail
```

复测报告模板：

```markdown
# TC-{ID} 复测报告

## 基本信息

| 项目 | 内容 |
|------|------|
| 用例编号 | TC-{ID} |
| 复测日期 | {date} |
| 复测批次 | {seq} |
| 复测结果 | ✅ 通过 / ❌ 失败 |
| 关联 Issue | #{issue-id} |

---

## 修复验证

| 步骤 | 操作 | 预期结果 | 实际结果 | 状态 |
|------|------|---------|---------|------|
| 1 | {原失败步骤} | {预期} | {实际} | ✅/❌ |

---

## 边界验证

| 步骤 | 操作 | 预期结果 | 实际结果 | 状态 |
|------|------|---------|---------|------|
| 1 | {边界测试} | {预期} | {实际} | ✅/❌ |

---

## 结论

{复测结论说明}
```

---

## 关键原则

| 原则 | 说明 |
|------|------|
| 复测不新建 Issue | 复测失败时 Reopen 原 Issue，不创建新 Issue |
| 补充失败信息 | 复测失败时必须补充详细的失败原因 |
| 验证边界场景 | 修复可能引入新问题，需要验证边界场景 |
| 记录复测批次 | 复测报告需要记录批次信息，便于追溯 |
