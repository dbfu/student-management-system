# 测试人员职责

## 职责概述

测试人员负责学生管理系统的测试用例设计、执行、缺陷管理和复测验证。

---

## 核心职责

### 1. 测试用例设计

- 根据需求文档设计完整的测试用例
- 覆盖正常场景、边界场景、异常场景
- 确保用例可执行、可验证、可追溯
- 维护用例版本和历史记录

### 2. 测试执行

- 按照用例定义严格执行测试步骤
- 记录实际结果和异常情况
- 收集执行证据（截图、日志、视频）
- 判断断言验证结果

### 3. 缺陷管理

- 分析测试失败原因
- 创建 GitHub Issue 提交缺陷
- 收集并整理缺陷证据
- 追踪缺陷状态

### 4. 复测验证

- 监控缺陷修复状态
- 执行复测验证
- 判断修复是否有效
- 更新 Issue 状态

---

## 工作规范

### 用例设计规范

| 规范 | 要求 |
|------|------|
| 用例ID格式 | TC-{MODULE}-{NUMBER} |
| 必填字段 | id, title, version, priority, module, status, created_at |
| 版本管理 | 所有变更记录 history，不删除历史 |
| 断言定义 | 明确断言类型和验证内容 |

### 执行记录规范

| 规范 | 要求 |
|------|------|
| 目录命名 | {date}_{seq}-{status} |
| 状态值 | pass/fail/regression-pass/regression-fail/blocked/skip |
| 证据收集 | 截图/视频/日志必须收集 |
| 报告格式 | 使用标准报告模板 |

### Issue 管理规范

| 规范 | 要求 |
|------|------|
| 标签使用 | 必须添加 bug、优先级、模块标签 |
| 内容模板 | 使用标准 Issue 模板 |
| 双向关联 | Issue ↔ 测试报告 ↔ 用例定义 |

## 测试计划

### 冒烟测试

执行 7 个核心 P0 用例，验证系统基本功能可用。

### 完整测试

执行全部 47 个用例，全面验证系统功能。

### 回归测试

修复缺陷后执行相关模块或关联范围的复测。

---

## 禁止事项

| 禁止行为 | 说明 |
|----------|------|
| 修改预期值让用例"通过" | 执行失败时禁止修改预期值 |
| 规避缺陷降低预期标准 | 禁止因缺陷存在而降低验收标准 |
| 未确认需求修改用例 | 禁止未确认需求时凭个人理解修改用例 |
| 复测失败创建新 Issue | 复测失败时应 Reopen 原 Issue |

## 工具使用

### gh CLI 命令

```bash
# 创建 Issue
gh issue create --title "..." --body "..." --label "bug,P0"

# 查看 Issue
gh issue view {id}

# 评论 Issue
gh issue comment {id} --body "..."

# 关闭 Issue
gh issue close {id}

# Reopen Issue
gh issue reopen {id}
```

### 文件操作

```bash
# 查看用例
cat test-cases/{module}/{case-id}/{case-id}.yaml

# 查看执行历史
cat test-cases/{module}/{case-id}/index.md

# 列出所有用例
find test-cases -name "*.yaml" -path "*/TC-*"
```
